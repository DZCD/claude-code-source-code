title: Team
description: Build coordination with AgentLike delegate tools and mailbox-based teams.

The SDK keeps team coordination centered on one interface: every callable boundary is an `AgentLike`.

- `agentTool()` exposes another `AgentLike` as a tool with explicit action modes.
- `createTeam()` wraps a lead agent with named member tools, inboxes, replies, and runtime wiring.
- `createTeamRunner()` is the advanced runtime behind mailbox-backed delegation.

`Agent` and `Team` satisfy the same `AgentLike` shape: they expose `query()` and `prompt()`. An `Agent` is the working subject with its own role, skills, tools, and workspace. A `Team` is a callable doorway to its lead, with the team's mailbox and member tools behind that lead.

The team API adds persistent collaboration semantics, but it is still intentionally small: it is not a separate agent personality, distributed scheduler, or workflow engine.

## Team as lead wrapper

Use `createTeam()` when you want to talk to the lead while that lead coordinates named members internally. The team automatically injects member `agentTool()` tools into the lead and drives the runtime when you call `team.query()` or `team.prompt()`.

```ts
import {
  createAgent,
  createMemoryMailbox,
  createTeam,
  teamMember,
} from "claude-team-agent-sdk";

const researcher = createAgent({
  apiKey: process.env.DEEPSEEK_API_KEY,
  baseURL: "https://api.deepseek.com/anthropic",
  model: "deepseek-v4-flash",
  systemPrompt: "You research agent SDK architecture and report concise findings.",
  workspace: ".agent-workspaces/researcher",
});

const team = createTeam({
  name: "engineering",
  lead: createAgent({
    apiKey: process.env.DEEPSEEK_API_KEY,
    baseURL: "https://api.deepseek.com/anthropic",
    model: "deepseek-v4-flash",
    systemPrompt: "You lead engineering work. Delegate research tasks to researcher.",
    workspace: ".agent-workspaces/engineering-lead",
  }),
  members: [
    teamMember({
      name: "researcher",
      role: "executor",
      focus: "Research agent architecture",
      agent: researcher,
    }),
  ],
  mailbox: createMemoryMailbox(),
});

for await (const event of team.query("Ask the researcher to inspect the SDK design.")) {
  console.log(event);
}
```

`team.query()` streams both the lead agent's normal SDK messages and team runtime events such as `team_message`, `team_agent`, and nested `agent_message` events. `team.prompt()` consumes that stream and returns only the final result.

Workspaces belong to agents, not teams or member definitions. Give each working agent its own `createAgent({ workspace })`, then have agents mention important workspace paths and verification notes in natural-language mailbox replies.

## Mailbox team

The team still exposes mailbox primitives for advanced flows that need explicit routing, durable storage, or manual draining.

```ts
import {
  createAgent,
  createMemoryMailbox,
  createTeam,
  teamMember,
} from "claude-team-agent-sdk";

const team = createTeam({
  name: "engineering",
  lead: createAgent({
    apiKey: process.env.DEEPSEEK_API_KEY,
    baseURL: "https://api.deepseek.com/anthropic",
    model: "deepseek-v4-flash",
  }),
  members: [
    teamMember({
      name: "researcher",
      role: "executor",
      focus: "Research agent architecture",
      agent: createAgent({
        apiKey: process.env.DEEPSEEK_API_KEY,
        baseURL: "https://api.deepseek.com/anthropic",
        model: "deepseek-v4-flash",
        workspace: ".agent-workspaces/researcher",
      }),
    }),
  ],
  mailbox: createMemoryMailbox(),
});

await team.prompt("Ask the researcher to inspect the SDK design.");
```

`createTeam()` injects member AgentLike tools into the lead. The lead calls members with an explicit action mode:

| Mode | Meaning |
| --- | --- |
| `ask` | Ask the member and wait for the final answer in the current tool call. |
| `handoff` | Assign work and get an acceptance receipt immediately. |
| `observe` | Start observable long-running work if the host runtime supports it. |

Member agents that can accept tools also receive mailbox tools for assigned work. If a member creates files, code, logs, or other durable deliverables, it should write them in its own workspace and report the relevant paths in `team_reply` or `team_followup` text.

| Tool | Purpose |
| --- | --- |
| `team_send` | Send an asynchronous message to another member. |
| `team_inbox` | List mailbox messages. |
| `team_read` | Read and claim a message. |
| `team_reply` | Send a final reply and close the original message. |
| `team_followup` | Send progress without closing the original message. |
| `team_status` | Summarize mailbox status counts. |

The lead does not receive raw mailbox tools by default. Use `exposeLeadMailboxTools: true` only for advanced flows where the lead should manually operate the team mailbox.

The default mailbox is in memory. For durable local storage, use `createSQLiteMailbox()` with a SQLite-like database:

```ts
import Database from "better-sqlite3";
import {
  createAgent,
  createSQLiteMailbox,
  createTeam,
} from "claude-team-agent-sdk";

const mailbox = createSQLiteMailbox({
  database: new Database("team-mailbox.db"),
});

const team = createTeam({
  name: "engineering",
  lead: createAgent({
    apiKey: process.env.DEEPSEEK_API_KEY,
    baseURL: "https://api.deepseek.com/anthropic",
    model: "deepseek-v4-flash",
  }),
  members: [],
  mailbox,
});
```

The SDK does not install a SQLite driver for you. This keeps the package free of native database dependencies and lets hosts choose `better-sqlite3`, Cloudflare D1 wrappers, or another compatible adapter.

Hosts that need distributed execution can provide their own `TeamMailbox` adapter.

## Nested teams

Because `teamMember().agent` accepts any `AgentLike`, a team wrapper can be a member of another team wrapper. This is how you model CEO -> Head Team -> Executor Agent without hard-coding that hierarchy into the SDK.

```ts
import {
  createAgent,
  createTeam,
  teamMember,
} from "claude-team-agent-sdk";

const createDeepSeekAgent = (systemPrompt: string, workspace: string) => createAgent({
  apiKey: process.env.DEEPSEEK_API_KEY,
  baseURL: "https://api.deepseek.com/anthropic",
  model: "deepseek-v4-flash",
  systemPrompt,
  workspace,
});

const ceoAgent = createDeepSeekAgent(
  [
    "You are the CEO agent.",
    "Clarify product goals, decide which department owns the work, and ask for concise progress reports.",
    "Do not implement engineering details yourself.",
  ].join("\n"),
  ".agent-workspaces/ceo",
);
const engineeringHeadAgent = createDeepSeekAgent(
  [
    "You are the engineering head agent.",
    "Break engineering goals into backend and frontend work, route tasks to the right executor, and report outcomes upstream.",
    "Keep architecture decisions explicit.",
  ].join("\n"),
  ".agent-workspaces/engineering-head",
);
const backendAgent = createDeepSeekAgent(
  [
    "You are the backend executor agent.",
    "Handle APIs, data models, storage, integrations, and server-side correctness.",
    "Escalate product or UI decisions instead of guessing.",
  ].join("\n"),
  ".agent-workspaces/backend",
);
const frontendAgent = createDeepSeekAgent(
  [
    "You are the frontend executor agent.",
    "Handle UI flows, client state, accessibility, and browser behavior.",
    "Escalate API contract questions instead of inventing them.",
  ].join("\n"),
  ".agent-workspaces/frontend",
);

const engineeringTeam = createTeam({
  name: "engineering",
  lead: engineeringHeadAgent,
  members: [
    teamMember({ name: "backend", role: "executor", agent: backendAgent }),
    teamMember({ name: "frontend", role: "executor", agent: frontendAgent }),
  ],
});

const companyTeam = createTeam({
  name: "company",
  lead: ceoAgent,
  members: [
    teamMember({
      name: "engineering",
      role: "head",
      focus: "Own engineering delivery",
      agent: engineeringTeam,
    }),
  ],
});
```

The CEO sees `engineeringTeam` as one member, but that member is still a callable wrapper around the engineering lead. The CEO is talking to the engineering lead; the engineering lead can internally route work to backend or frontend.

## Routing loops

The SDK does not block routing loops by default. A task can move from a manager to a member, back to the manager for context, and then back to the same member. That is normal organizational flow, not necessarily a runtime error.

Use `maxTurns`, permission callbacks, mailbox status, and host-level monitoring to control cost and risk. If your application needs a strict hierarchy, expose only the allowed members at each layer and enforce routing with permission callbacks or a host-level policy.

## Drain routed work

Team routing is explicit. A pending message belongs to its `to` mailbox and must be handled by that member's agent. The mailbox does not expose a global task pool.

Use `claimNext(mailboxId)` to claim one pending message for a specific member:

```ts
const message = await team.mailbox.claimNext("engineering::researcher");
```

Use `team.drain()` to advance already-routed work:

```ts
const result = await team.drain({
  maxRounds: 5,
  maxMessages: 20,
});
```

`drain()` iterates members, claims messages from each member's own mailbox, and prompts that member agent. It does not choose a different agent.

Each member must close the loop with one of these tools:

| Tool | Effect |
| --- | --- |
| `team_reply` | Sends the final result upstream and marks the original message `done`. |
| `team_followup` | Sends progress upstream while leaving the original message open. |

If the member agent ends without either tool, `drain()` marks the original message `failed` and sends a diagnostic follow-up to the upstream mailbox.
