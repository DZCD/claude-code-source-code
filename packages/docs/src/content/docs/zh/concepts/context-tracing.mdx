---
title: 上下文追踪
description: 记录 agent 运行、工具调用和团队委托上下文。
---

上下文追踪让宿主应用在不改变 agent loop 的情况下观察运行过程。SDK 会通过
很小的 `ContextTracer` 接口输出结构化事件。内置 tracer 可以把事件写成本地
JSONL，也可以把事件投影到 LangSmith。

追踪是 append-only 的可观测性能力，不等于 resume。当前 `Agent` 的对话状态仍然
只在实例生命周期内保存在内存中。

## JSONL tracer

需要本地调试、审计日志或测试产物时，可以使用 `createJsonlContextTracer()`。

```ts
import { createAgent, createJsonlContextTracer } from "claude-team-agent-sdk";

const tracer = createJsonlContextTracer({
  path: ".agent-runs/session.jsonl",
});

const agent = createAgent({
  apiKey: process.env.DEEPSEEK_API_KEY,
  baseURL: "https://api.deepseek.com/anthropic",
  model: "deepseek-v4-flash",
  tracer,
});

await agent.prompt("记住我的名字是 Ada。", {
  stream: false,
});
```

每一行 JSONL 都是一个独立对象：

```json
{
  "version": 1,
  "timestamp": "2026-06-28T12:00:00.000Z",
  "session_id": "session-id",
  "run_id": "run-id",
  "seq": 1,
  "source": { "kind": "agent", "name": "agent" },
  "type": "user_message",
  "data": {
    "message": {
      "role": "user",
      "content": "记住我的名字是 Ada。"
    }
  }
}
```

如果传入 `dir` 而不是 `path`，tracer 会按 session 写文件：

```ts
const tracer = createJsonlContextTracer({
  dir: ".agent-runs",
});
```

## LangSmith tracer

需要把 SDK 运行显示成 LangSmith trace 时，可以使用
`createLangSmithContextTracer()`。宿主应用自行安装 `langsmith`，并把它的
`RunTree` 构造器传给 tracer。

按 LangSmith 官方方式配置环境变量：

```bash
LANGSMITH_TRACING=true
LANGSMITH_ENDPOINT=https://api.smith.langchain.com
LANGSMITH_API_KEY=<your-langsmith-api-key>
LANGSMITH_PROJECT=<your-langsmith-project>
```

```ts
import { RunTree } from "langsmith/run_trees";
import { createAgent, createLangSmithContextTracer } from "claude-team-agent-sdk";

const tracer = createLangSmithContextTracer({
  RunTree,
  projectName: process.env.LANGSMITH_PROJECT,
  tags: ["local-debug"],
});

const agent = createAgent({
  apiKey: process.env.DEEPSEEK_API_KEY,
  baseURL: "https://api.deepseek.com/anthropic",
  model: "deepseek-v4-flash",
  tracer,
});
```

如果你想自己构造 LangSmith client，也可以显式传入 `Client`。`workspaceId`
是可选的，只用于选择 LangSmith workspace；它不是 trace project 名。

```ts
import { Client } from "langsmith";
import { RunTree } from "langsmith/run_trees";
import { createLangSmithContextTracer } from "claude-team-agent-sdk";

const langsmithClient = new Client({
  apiKey: process.env.LANGSMITH_API_KEY,
  apiUrl: process.env.LANGSMITH_ENDPOINT,
  // 可选：只有 LangSmith 账号需要显式指定 workspace 时才传。
  // workspaceId: process.env.LANGSMITH_WORKSPACE_ID,
});

const tracer = createLangSmithContextTracer({
  RunTree,
  client: langsmithClient,
  projectName: process.env.LANGSMITH_PROJECT,
});
```

SDK 不 import LangSmith，也不把它作为硬依赖。LangSmith tracer 和 JSONL tracer
一样只是实现 `ContextTracer`，所以 agent loop 不需要知道具体观测后端。

LangSmith 会收到这样的投影：

| SDK 事件序列 | LangSmith 投影 |
| --- | --- |
| `run_start` 到 `result` | 根 `chain` run。 |
| `model_request` 到 `assistant_message` | 子 `llm` run。 |
| `tool_use` 到 `tool_result` | 子 `tool` run。 |
| `team_message` 和其它辅助事件 | 当前 chain 上的 run event。 |

可以用 `createCompositeContextTracer()` 把同一份 trace stream 同时发送到多个
sink：

```ts
const tracer = createCompositeContextTracer([
  createJsonlContextTracer({ path: ".agent-runs/session.jsonl" }),
  createLangSmithContextTracer({
    RunTree,
    projectName: process.env.LANGSMITH_PROJECT,
  }),
]);
```

## 事件类型

| 类型 | 说明 |
| --- | --- |
| `run_start` | Agent run 元数据，包括模型和工具名。 |
| `user_message` | 加入模型上下文的用户消息或工具结果消息。 |
| `model_request` | 模型请求上下文，包括选中的 messages、tools 和 stream 模式。 |
| `assistant_message` | 模型客户端返回的 assistant message。 |
| `tool_use` | Assistant 请求的工具调用。 |
| `tool_result` | SDK 产生并回填给模型的工具结果。 |
| `result` | 本次 query 的最终结果，包括成功和错误 subtype。 |

`seq` 在同一个 tracer 实例中单调递增。UI 或日志管线可以用 `session_id`、
`run_id` 和 `source` 来分组。

## Team 追踪

在 `team.query()` 或 `createTeamRunner().query()` options 中传入 tracer，可以把
同一个追踪 sink 传递给被委托的子 agent。

```ts
for await (const event of team.query("请 engineering 检查 tracing 设计。", {
  tracer,
})) {
  console.log(event);
}
```

被委托的 agent 会带上运行来源：

```json
{
  "source": {
    "kind": "team_member",
    "name": "engineering",
    "member": "engineering",
    "mailbox": "engineering"
  },
  "type": "result",
  "data": {
    "subtype": "success",
    "result": "Engineering result"
  }
}
```

即使根 agent 通过 team 或嵌套 team 委托工作，JSONL 也能保持可读。

## 自定义 sink

`ContextTracer` 很小，宿主可以写入自己的数据库或可观测性系统。下面这些函数
是宿主应用自己实现的代码，不是 SDK 导出的 API：

```ts
import type { ContextTracer } from "claude-team-agent-sdk";

const tracer: ContextTracer = {
  async onEvent(event) {
    // TODO: 替换成你自己的数据库写入逻辑。
  },
  async flush() {
    // TODO: 替换成你自己的缓冲区 flush 逻辑。
  },
};
```

只有当 trace 持久性是产品契约的一部分时，才建议使用 `failOnError: true`。
默认情况下，tracing 应该是旁路观察，不应该让 agent run 失败。

## 脱敏

Trace 事件可能包含 prompt、模型上下文、工具输入和工具输出。写入 JSONL 前可以
使用 `redact` 执行本地策略。

`redact` 是你传给 SDK 的回调函数。JSONL tracer 在写入每个 trace event 前，
会先把 event 传给这个回调。回调可以返回原 event、返回修改后的副本，或者返回
`undefined` 来跳过这个 event。这只会改变写入 trace 文件的内容，不会改变真正
发给模型的请求。

```ts
const tracer = createJsonlContextTracer({
  path: ".agent-runs/session.jsonl",
  redact(event) {
    if (event.type === "model_request") {
      return {
        ...event,
        data: {
          ...event.data,
          messages: "[redacted]",
        },
      };
    }
    return event;
  },
});
```

这个例子会在持久化前把 `model_request.data.messages` 替换成
`"[redacted]"`。这个字段通常可能包含用户 prompt、对话历史和工具结果，所以常常
是本地隐私策略优先处理的位置。其它事件类型会原样写入。

从 `redact` 返回 `undefined` 可以跳过整个事件：

```ts
const tracer = createJsonlContextTracer({
  path: ".agent-runs/session.jsonl",
  redact(event) {
    if (event.type === "tool_result") {
      return undefined;
    }
    return event;
  },
});
```
