---
title: 子智能体委派和团队
description: 在一次性 supervisor 委派和持久 mailbox team 之间选择。
---

AgentLattice 里有两种相关但不同的协作模式。设计应用时应该先把它们分开：

- [Supervisor 子智能体委派](/zh/concepts/supervisor-delegation/)：适合一次性的子智能体。主智能体把另一个 `AgentLike` 暴露成工具，等待子智能体结果作为 tool result，然后继续自己的回合。
- [Mailbox Team 持久团队](/zh/concepts/mailbox-team/)：适合持久运转的团队。lead 通过 mailbox-backed work item、成员 inbox、回复、状态、持久化和可选手动 drain 来协调命名成员。

两者共用同一个核心约束：每个可调用边界都是 `AgentLike`。差别在生命周期。

| 模式 | 适用场景 | 主要 API |
| --- | --- | --- |
| Supervisor 子智能体委派 | 主智能体需要一个临时专家，例如 explore、plan、review 或一次性实现辅助。 | `agentTool()` + `mode: "ask"` |
| Mailbox Team 持久团队 | 工作需要成为可路由、可领取、可回复、可检查、可持久化的团队消息。 | `createTeam()` 和 `createTeamRunner()` |

如果只是“主智能体现在调用一个 helper 拿一个结果”，从 supervisor 委派开始。如果工作应该留在团队 mailbox 里，并带有明确状态、回复和持久化语义，使用 mailbox team。
