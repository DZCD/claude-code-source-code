title: Team 团队
description: 使用 AgentLike 委托工具和 mailbox team 构建团队协作。
---

SDK 的团队协作围绕一个核心接口：每个可调用边界都是 `AgentLike`。

- `agentTool()`：把另一个 `AgentLike` 暴露成带明确行动模式的工具。
- `createTeam()`：把 lead agent 包装上命名成员工具、inbox、回复和 runtime wiring。
- `createTeamRunner()`：底层高级 runtime，用于自定义 mailbox-backed 委托。

`Agent` 和 `Team` 都满足同一个 `AgentLike` 形状：它们都暴露 `query()` 和 `prompt()`。`Agent` 是真正工作的主体，拥有自己的角色、skills、tools 和 workspace。`Team` 是通向 lead 的可调用入口，lead 背后挂着团队 mailbox 和成员工具。

Team 不是另一个 agent 人格，也不是完整的分布式调度器。它提供的是可组合的组织/runtime 抽象，宿主应用可以在此基础上接入自己的存储、队列和 worker runtime。

## Team 作为 lead wrapper

当你想直接和 lead 对话，同时让这个 lead 在内部协调命名成员时，使用 `createTeam()`。Team 会自动把成员注入成 lead 可用的 `agentTool()` 工具，并在你调用 `team.query()` 或 `team.prompt()` 时驱动 runtime。

```ts
import {
  createAgent,
  createMemoryMailbox,
  createTeam,
  teamMember,
} from "claude-team-agent-sdk";

const researcher = createAgent({
  apiKey: process.env.DEEPSEEK_API_KEY,
  baseURL: "https://api.deepseek.com/anthropic",
  model: "deepseek-v4-flash",
  systemPrompt: "你负责调研 agent SDK 架构，并输出简洁结论。",
  workspace: ".agent-workspaces/researcher",
});

const team = createTeam({
  name: "engineering",
  lead: createAgent({
    apiKey: process.env.DEEPSEEK_API_KEY,
    baseURL: "https://api.deepseek.com/anthropic",
    model: "deepseek-v4-flash",
    systemPrompt: "你是工程负责人。需要调研时委托 researcher。",
    workspace: ".agent-workspaces/engineering-lead",
  }),
  members: [
    teamMember({
      name: "researcher",
      role: "executor",
      focus: "Research agent architecture",
      agent: researcher,
    }),
  ],
  mailbox: createMemoryMailbox(),
});

for await (const event of team.query("请让 researcher 检查 SDK 设计。")) {
  console.log(event);
}
```

`team.query()` 会同时输出 lead agent 的普通 SDK 消息，以及 `team_message`、`team_agent`、嵌套 `agent_message` 等团队 runtime 事件。只需要最终结果时，使用 `team.prompt()`。

workspace 属于 agent，不属于 Team 或 team member 定义。每个 agent 都会在 `~/.agent/workspaces` 下获得默认 workspace；只有宿主想覆盖默认位置时才需要传入 `workspace`。agent 应该在 mailbox 回复里用自然语言说明重要 workspace 路径和验证结果。

## Mailbox team

团队仍然暴露 mailbox 原语，适合需要显式路由、持久化存储或手动 drain 的高级场景。

```ts
import {
  createAgent,
  createMemoryMailbox,
  createTeam,
  teamMember,
} from "claude-team-agent-sdk";

const team = createTeam({
  name: "engineering",
  lead: createAgent({
    apiKey: process.env.DEEPSEEK_API_KEY,
    baseURL: "https://api.deepseek.com/anthropic",
    model: "deepseek-v4-flash",
  }),
  members: [
    teamMember({
      name: "researcher",
      role: "executor",
      focus: "Research agent architecture",
      agent: createAgent({
        apiKey: process.env.DEEPSEEK_API_KEY,
        baseURL: "https://api.deepseek.com/anthropic",
        model: "deepseek-v4-flash",
        workspace: ".agent-workspaces/researcher",
      }),
    }),
  ],
  mailbox: createMemoryMailbox(),
});
```

`createTeam()` 会把成员 AgentLike 工具注入 lead。lead 调用成员时要使用明确的行动模式：

| 模式 | 含义 |
| --- | --- |
| `ask` | 询问该成员，并在当前工具调用里等待最终答案。 |
| `handoff` | 把任务交给该成员，并立即获得接收回执。 |
| `observe` | 在宿主 runtime 支持时，启动可观察的长任务。 |

能够接收工具的成员还会获得 mailbox tools，用于处理分配给自己的消息。如果成员创建了文件、代码、日志或其它持久化交付物，应写入自己的 workspace，并在 `team_reply` 或 `team_followup` 文本里说明相关路径。

| 工具 | 作用 |
| --- | --- |
| `team_send` | 给指定成员发送异步消息。 |
| `team_inbox` | 查看当前 mailbox 里的消息。 |
| `team_read` | 读取并领取一封消息。 |
| `team_reply` | 发送最终结果，并把原消息标记为 `done`。 |
| `team_followup` | 发送阶段性进展，不关闭原消息。 |
| `team_status` | 查看 mailbox 状态统计。 |

lead 默认不会获得 raw mailbox tools。只有高级场景中确实需要 lead 手动操作团队 mailbox 时，才设置 `exposeLeadMailboxTools: true`。

## 持久化 mailbox

默认 `createMemoryMailbox()` 只保存在内存里。需要本地持久化时，可以使用 SQLite adapter：

```ts
import Database from "better-sqlite3";
import {
  createAgent,
  createSQLiteMailbox,
  createTeam,
} from "claude-team-agent-sdk";

const mailbox = createSQLiteMailbox({
  database: new Database("team-mailbox.db"),
});

const team = createTeam({
  name: "engineering",
  lead: createAgent({
    apiKey: process.env.DEEPSEEK_API_KEY,
    baseURL: "https://api.deepseek.com/anthropic",
    model: "deepseek-v4-flash",
  }),
  members: [],
  mailbox,
});
```

SDK 不内置 SQLite 驱动。这样可以避免强制安装 native dependency，也方便宿主应用自己选择 `better-sqlite3`、Cloudflare D1 wrapper 或其它兼容实现。

## 嵌套团队

因为 `teamMember().agent` 接受任意 `AgentLike`，一个 team wrapper 可以成为另一个 team wrapper 的成员。这个模式可以表达 CEO -> Head Team -> Executor Agent，而不需要把层级写死在 SDK 里。

```ts
import {
  createAgent,
  createTeam,
  teamMember,
} from "claude-team-agent-sdk";

const createDeepSeekAgent = (systemPrompt: string, workspace: string) => createAgent({
  apiKey: process.env.DEEPSEEK_API_KEY,
  baseURL: "https://api.deepseek.com/anthropic",
  model: "deepseek-v4-flash",
  systemPrompt,
  workspace,
});

const ceoAgent = createDeepSeekAgent(
  [
    "你是 CEO agent。",
    "你负责澄清产品目标，判断工作应该交给哪个部门，并要求下级给出简洁进展汇报。",
    "不要自己实现工程细节。",
  ].join("\n"),
  ".agent-workspaces/ceo",
);
const engineeringHeadAgent = createDeepSeekAgent(
  [
    "你是工程负责人 agent。",
    "你负责把工程目标拆成 backend 和 frontend 工作，显式路由给合适的执行者，并向上级汇报结果。",
    "架构决策要说清楚。",
  ].join("\n"),
  ".agent-workspaces/engineering-head",
);
const backendAgent = createDeepSeekAgent(
  [
    "你是 backend 执行 agent。",
    "你负责 API、数据模型、存储、集成和服务端正确性。",
    "遇到产品或 UI 决策时向上级反馈，不要擅自假设。",
  ].join("\n"),
  ".agent-workspaces/backend",
);
const frontendAgent = createDeepSeekAgent(
  [
    "你是 frontend 执行 agent。",
    "你负责 UI 流程、客户端状态、可访问性和浏览器行为。",
    "遇到 API 契约问题时向上级反馈，不要自行发明接口。",
  ].join("\n"),
  ".agent-workspaces/frontend",
);

const engineeringTeam = createTeam({
  name: "engineering",
  lead: engineeringHeadAgent,
  members: [
    teamMember({ name: "backend", role: "executor", agent: backendAgent }),
    teamMember({ name: "frontend", role: "executor", agent: frontendAgent }),
  ],
});

const companyTeam = createTeam({
  name: "company",
  lead: ceoAgent,
  members: [
    teamMember({
      name: "engineering",
      role: "head",
      focus: "Own engineering delivery",
      agent: engineeringTeam,
    }),
  ],
});
```

CEO 看到的是一个 `engineeringTeam` 成员，但这个成员仍然是通向工程负责人的 callable wrapper。CEO 实际上是在和工程负责人对话；工程负责人可以在内部继续把工作路由给 backend 或 frontend。

## 路由回流

SDK 默认不会阻止路由回流。任务可以从 manager 发给成员，成员为了补充上下文再发回 manager，然后 manager 再把任务交回同一个成员。这是正常的组织协作流，不一定是 runtime 错误。

控制成本和风险时，优先使用 `maxTurns`、权限回调、mailbox 状态和宿主侧监控。如果你的应用需要严格层级，可以只向每一层暴露允许访问的成员，并通过权限回调或宿主侧 routing policy 约束消息流向。

## 显式路由和 claimNext

团队消息不是全局任务池。每条 pending 消息都有明确的 `to` mailbox，必须由对应成员处理。

```ts
const message = await team.mailbox.claimNext("engineering::researcher");
```

`claimNext(mailboxId)` 只会领取这个 mailbox 的一条 `pending` 消息，并把它改成 `processing`。它不会重新判断“这个任务该给谁”。

## team.drain()

`team.drain()` 用来推进已经显式路由的任务：

```ts
const result = await team.drain({
  maxRounds: 5,
  maxMessages: 20,
});
```

它会遍历团队成员，从每个成员自己的 mailbox 里 claim 消息，然后提示该成员 agent 处理。

成员处理完必须向上级反馈：

- 有最终结果时调用 `team_reply`。
- 还在处理中时调用 `team_followup`。

如果成员 agent 结束时既没有 `team_reply`，也没有 `team_followup`，runtime 会把原消息标记为 `failed`，并向上级 mailbox 发送一条诊断性 follow-up。这样可以避免任务进入“处理了但没人汇报”的黑洞。
